# 04.2. API Client Layer & Axios Interceptors

Velora routes all frontend HTTP requests through a unified, resilient Axios client located in [`Frontend/src/api/client.js`](file:///h:/Omid/Code/Velora/Frontend/src/api/client.js).

## 1. Interceptor Architecture & Lifecycle

```mermaid
sequenceDiagram
    autonumber
    actor Component as "React Component / Hook"
    participant Client as "Axios Client (client.js)"
    participant ReqInt as "Request Interceptor"
    participant Server as "Express Backend"
    participant ResInt as "Response Interceptor"
    participant RefreshQueue as "Silent Refresh Queue"
    participant Redux as "Redux Store & Storage"

    Component->>Client: client.get("/server/cart")
    Client->>ReqInt: Intercept request
    ReqInt->>ReqInt: Inject "Authorization: Bearer <accessToken>"
    ReqInt->>Server: Forward HTTP Request
    
    alt Token Valid (200 OK)
        Server-->>ResInt: Return 200 OK Response
        ResInt-->>Component: Deliver data
    else Token Expired (401 Unauthorized)
        Server-->>ResInt: Return 401 Unauthorized
        ResInt->>RefreshQueue: Check if refresh in-flight
        alt Already Refreshing
            RefreshQueue->>RefreshQueue: Push request to pendingQueue
        else First 401 Request
            RefreshQueue->>Server: POST /server/.../token/refresh (refreshToken)
            alt Refresh Succeeded
                Server-->>RefreshQueue: New Access Token
                RefreshQueue->>Redux: saveAuthSession({ token: newToken })
                RefreshQueue->>Client: Replay original request with new token
                RefreshQueue->>RefreshQueue: Resolve all queued pending requests
                Client-->>Component: Return replayed response
            else Refresh Failed / Expired
                Server-->>RefreshQueue: 401 Refresh Failed
                RefreshQueue->>Redux: expireSession() -> clearAuthSession() & clear Redux
                RefreshQueue->>Component: Reject with Session Expired Error
            end
        end
    end
```

## 2. Implementation Highlights

### 2.1. Request Interceptor: Token Injection
```javascript
client.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

### 2.2. Dynamic Role Refresh Endpoint Resolution
The client dynamically chooses the appropriate refresh route based on active Redux auth state:
```javascript
function getRefreshEndpoint() {
  const authState = store.getState()?.auth;
  if (authState?.storeOwner) {
    return "/server/store-owner/token/refresh";
  }
  return "/server/customer/token/refresh";
}
```

### 2.3. Pending Request Queue
When multiple parallel requests fail simultaneously due to an expired access token, only **one** refresh request is dispatched to the backend. All other requests are queued in `pendingQueue` and replayed automatically once the new token is acquired.

### 2.4. Session Expiration & Cleanup
When refresh fails (e.g., refresh token expired), `expireSession()` clears credentials and resets Redux state:
```javascript
function expireSession() {
  clearAuthSession();
  store.dispatch(clearAuth());
  store.dispatch(clearUserProfile());
  store.dispatch(clearStoreOwnerProfile());
}
```
